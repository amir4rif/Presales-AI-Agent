# Ramssol Pre-Sales Copilot

Next.js application for prospect research, proposal versioning, approvals, pipeline tracking, and analytics.

The default offline mode uses authored seed data. The shared free-tier path uses Supabase for Postgres, Auth, RLS, and proposal Realtime; Google Gemini for AI; optional SerpApi Brave AI Mode for sourced prospect research; and Vercel for hosting.

```text
Browser ──► Supabase Auth (cookie session)
   │
   ├──────► /api/data ──► Supabase Postgres + RLS
   │                         └─ proposals Realtime ──► browser refresh
   ├──────► /api/generate ──► Gemini (Anthropic adapter retained)
   └──────► /api/research ──► SerpApi Brave AI Mode (optional)
```

The Lark server modules and `/api/lark` remain in the repository as a dormant future adapter. They are not selectable through `DATA_SOURCE`.

## Local setup

Requirements: Node.js 22 or later.

```bash
npm install
copy .env.example .env.local
npm run check:env
npm run dev
```

Open <http://localhost:3000>. With `DATA_SOURCE=seed`, the login page offers password-free Level 1, 2, and 3 personas. Seed mode stores demo edits in the browser only and never calls Supabase.

## Supabase setup

1. Create or select the **Ramssol Pre-Sales Copilot** project.
2. Apply every file in `supabase/migrations/` in filename order with the Supabase CLI or dashboard migration workflow.
3. Copy the Project URL and an enabled `sb_publishable_...` key into `.env.local`:

   ```dotenv
   DATA_SOURCE=supabase
   NEXT_PUBLIC_SUPABASE_URL=https://PROJECT_REF.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```

4. In Supabase Auth URL Configuration, set the local Site URL to `http://localhost:3000` and allow `http://localhost:3000/auth/**` as a redirect URL. Add the matching Vercel URLs before deployment.
5. Create accounts through the application. New users always start at Level 1; this is intentional so user-editable signup metadata cannot grant authorization.
6. Bootstrap the first administrator once in the Supabase SQL Editor, replacing the email with the intended administrator account:

   ```sql
   update public.profiles
   set role = 'Sales Operations', level = 3
   where email = 'administrator@company.com';
   ```

   After that, the Level 3 user can assign reviewer and administrator roles in Settings.
7. Run `npm run check:env:strict`, then sign in and test the full workflow.

The migration creates real `profiles`, `proposals`, `deals`, `closed_deals`, and `prospects` tables plus three security-invoker views:

- `my_proposals`: current owner, excluding Superseded and Reject & Close.
- `admin_approvals`: Pending Review rows visible through base-table RLS.
- `proposal_version_history`: visible versions ordered by case and version.

Level 1 can read/write owned rows. Levels 2 and 3 can see team rows. On deals, closed deals, and prospects, Level 2 may edit team rows but cannot reassign them and may delete only their own; Level 3 retains full control. Reviewer-only proposal transitions are enforced in Postgres, proposal rows have no delete grant, and case numbers are generated by a database sequence. The `proposals` table is added to the `supabase_realtime` publication.

## AI and research

Gemini is the default provider:

```dotenv
AI_PROVIDER=gemini
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.6-flash
```

`/api/generate` keeps the original browser request and response contract. The provider adapter maps the existing effort option to a Gemini thinking budget and returns a clear `429` message when a free-tier quota is exhausted. Set `AI_PROVIDER=anthropic` and the documented Anthropic variables to use the retained fallback.

Optional sourced prospect research is server-only:

```dotenv
SERPAPI_API_KEY=
```

When configured, `/api/research` requests SerpApi's `brave_ai_mode` engine, returns a bounded summary and source links, and supplies that verified context to the prospect research prompt. Without the key, the feature still works through Gemini but explicitly treats financial and headcount values as estimates.

## Vercel deployment

1. Import the repository into Vercel and select the repository root.
2. Use Node.js 22 or later.
3. Add the Supabase, Gemini, and optional SerpApi variables to Preview and Production. Do not add a Supabase secret/service-role key to any `NEXT_PUBLIC_` variable.
4. Add the Vercel domains to Supabase Auth Site URL / Redirect URLs.
5. Deploy, then run the Level 1 → Level 2 review flow with three real accounts.

The runtime does not write to the filesystem. Supabase clients and user state are created per request; no authenticated client or session is cached at module scope.
